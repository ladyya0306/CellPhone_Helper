### 0.1 一个必须先解决的前置问题

**当前 App 没有 `INTERNET` 权限**（已确认）——它现在根本无法联网。
这意味着：云端交接（L2）、搜索、行情**全都做不了**，直到加上这个权限。

加权限本身是一行 XML，但**必须同时做**：
- 在设置里明确"联网开关"
- 每次联网前告知（或提供域名白名单）
- 因为这会**打破"完全离线"的承诺**

## 2. 本地 / 云端边界与交接

### 2.1 两级路由（L3 降为可选）

| 级别 | 场景 | 交给谁 | 说明 |
|---|---|---|---|
| **L1 本地（默认）** | 闲聊、人设对话、简单工具（待办/闹钟/时间）、模板心跳 | 本地 4B | 零成本、零延迟、隐私不出机 |
| **L2 云端整轮接管（默认升级）** | 长文档总结、复杂推理、写代码、多语言、精细读图 | 云端 | 云端能看到完整对话，直接给答案，最可靠 |
| *L3 云端规划 + 本地执行（可选，非默认）* | 必须操作手机且步骤多的任务 | 云端出计划 → 本地逐步执行 | 仅在某类任务上启用，每步确认 |

### 2.2 L2 交接协议（默认路径）

```
用户请求
  ↓
本地判定"我可能做不好"（规则 + 本地自评）
  ↓
弹确认框：列出将上传的内容摘要
  ├─ 用户拒绝 → 本地尽力 + 说明局限
  └─ 用户同意 ↓
       把会话上下文发给云端（带同一套 tools 定义）
       ↓
       云端返回结果（可能是纯文本，也可能是 tool_calls）
       ├─ 纯文本 → 本地用人设口吻润色 → 输出
       └─ tool_calls → 本地执行 → 结果回灌云端 → 云端收尾
  ↓
会话里打标「来源=云端」
```

**成本闸门（保留）**：
- 每次升级**必须确认**（不提供"总是同意"）
- 心跳**绝不触发云端**（自动 + 云端 = 账单失控）
- 每日 token 上限（默认 5 万）

### 2.3 为什么 L2 优于 L3（已论证）

| 代价 | L3（云端指导本地） |
|---|---|
| 多次往返 | 5 步任务要 5+ 次云端调用 |
| 成本放大 | 每次往返重发上下文 |
| 可靠性 | 执行仍受限于本地 4B 的工具调用能力 |

**L2 = 云端一次干完**，本地只负责"加人设口吻"。90% 的升级场景够用。

## 4. 联网搜索与行情（改为：做，但要设计好）

### 4.1 关键结论：不需要付费 API

| 能力 | 免费端点 | 说明 |
|---|---|---|
| **搜索** | `https://html.duckduckgo.com/html/?q=<词>` | 返回 HTML，Jsoup 提取 `.result__a` / `.result__snippet` |
| 搜索（备选） | 公开 SearXNG 实例的 JSON 接口 | 部分实例禁用 JSON，需实测 |
| **行情** | `https://hq.sinajs.cn/list=sh600519,sh601398` | 需带 `Referer: https://finance.sina.com.cn` |
| 行情（备选） | `https://qt.gtimg.cn/q=sh600519` | 返回 `v_sh600519="1~贵州茅台~600519~1680.00~..."` |
| **读正文** | Jsoup 解析任意网页 → 纯文本 | 唯一新增依赖（~400KB） |

### 4.2 代价要如实说

| 风险 | 说明 | 缓解 |
|---|---|---|
| **脆弱** | 对方改版/改接口就挂 | 做成**可插拔数据源**，一个接口挂了换另一个 |
| **限流/封 IP** | 高频请求可能被限制 | 结果缓存（搜索 10 分钟、行情 1 分钟） |
| **合规** | 公开接口非正式 API，商用有风险 | **仅自用**，界面上注明数据来源 |
| **破坏离线承诺** | 联网 = 数据出机 | 默认关，显式开关，每次告知 |

### 4.3 设计：可插拔数据源（关键）

```
interface SearchProvider { suspend fun search(q: String, limit: Int): List<SearchHit> }
   ├─ DuckDuckGoHtmlProvider   （免费，默认）
   └─ BraveApiProvider         （付费，将来可插）

interface QuoteProvider { suspend fun quotes(symbols: List<String>): List<Quote> }
   ├─ SinaQuoteProvider        （免费，默认）
   ├─ TencentQuoteProvider     （免费，备选）
   └─ 付费数据源              （将来可插）

data class SearchHit(val title: String, val url: String, val snippet: String)
data class Quote(val symbol: String, val name: String, val price: Double,
                 val changePct: Double, val time: String)
```

**这样换数据源不需要改业务代码**——这就是 Hermes 式系统的做法。

### 4.4 依赖

- `INTERNET` 权限（**当前缺失，必须加**）
- Jsoup（HTML 解析，唯一新增 Gradle 依赖）
- HTTP 用标准库 `HttpURLConnection` 即可，不引入 OkHttp

## 5. 工作状态判定（做，但默认关闭）

### 5.1 权限

`PACKAGE_USAGE_STATS` **不是普通权限**，需在「设置 → 特殊应用权限 → 使用情况访问」手动授予。
App 只能引导跳转：`Intent(Settings.ACTION_USAGE_ACCESS_SETTINGS)`。

### 5.2 判定逻辑

```
working =
    (在工作时段内 且 办公类 App 累计使用 > 30 分钟)
  || (连续使用手机 > 2 小时)              // 该休息了
resting  = 工作时段内 且 娱乐类 App 使用 > 20 分钟
idle     = 连续 30 分钟无操作
sleeping = 免打扰时段 或 屏幕关闭 > 1 小时
```

App 分类内置一张表（微信/钉钉/飞书/邮件/文档 = 办公；抖音/B站/游戏 = 娱乐），用户可自定义。

### 5.3 隐私边界（严格控制）

- **默认关闭**，Onboarding 里明确询问才启用
- 只读"前台包名 + 使用时长"，**不读内容、不上传**
- 设置页随时可关，关闭后立即停止读取
- 设置页显示"当前判定状态"，用户可验证是否准确

## 6. 心跳打磨：从"定时说话"到"事件驱动的价值推送"

**本次最重要的改造。**

### 6.1 现状问题

现在是**定时 + 模板 + 随机话术**。`topic=care` 说"小咪来蹭蹭主人喵～"——
**这条信息没有任何具体价值**，说 3 次就烦。这就是"小吵闹"的根源。

### 6.2 改造：触发源多样化 + 价值判断 + 聚合

**触发源（去掉新闻/行情后，实际可用的）**：

| 类型 | 触发条件 | 例子 | 优先级 |
|---|---|---|---|
| **事件·紧急** | 待办 30 分钟内到期 | "15:30 的会议还有 20 分钟" | 高 |
| **事件·有用** | 用户配置的倒计时到点 | "还有 3 天是小林的生日" | 中 |
| **状态·关怀** | 连续工作 2 小时（需 UsageStats） | "该起来动动了" | 中 |
| **状态·问候** | 早上第一次解锁 | "早，今天有三个待办" | 中 |
| **定时·兜底** | 每天 2–3 次 | 人设话术 | 低 |

> 新闻/行情触发因外部依赖暂缺，保留接口位（`WatchSource` 抽象），将来接入即可。

**价值判断三问（开口前必须过）**：
1. **有具体信息吗？** 没有 → 只允许低频情绪价值（且降频）
2. **此刻方便吗？** 工作中 → 只推紧急；免打扰 → 闭嘴；刚聊完 → 等
3. **今天说了几次？** 超预算 → 聚合到下次

**聚合机制（关键）**：多条信息合并成**一条**，而不是逐条推送：
> "今天有 3 件事：15:30 开会 · 茅台（示例）· 还有 3 天是小林生日"

这一条直接解决"小吵闹"。

### 6.3 内容偏向（**全局设置**）

设置项：`心跳内容偏向 = 实用优先 / 情绪优先 / 平衡`（全局唯一开关，不做每人设默认）

| 偏向 | 待办提醒 | 纯问候（无具体信息时） |
|---|---|---|
| 实用优先 | "15:30 开会，还有 20 分钟" | 基本不生造问候 |
| 情绪优先 | "主人～15:30 有会哦，小咪提醒你喵" | "主人今天过得怎么样喵～" |
| 平衡（默认） | "15:30 有会，别忘了；小咪在这儿等你喵" | 低频问候 |

**关键原则**：偏向只影响**说什么内容和多少语气**，不改变人设**说话方式**（自称/称呼/口癖）。

### 6.4 状态与心跳联动

```
working  → 只推：紧急待办；压制问候类
resting  → 允许：轻度提醒、情绪价值
idle     → 允许：问候、聚合日报
sleeping → 全部静默
```
（UsageStats 未开启时，全部按 `idle` 处理）

## 7. 初始化引导（Onboarding）

现在所有心跳参数都靠用户去设置页摸索，体验很差。**六步引导**：

| 步 | 内容 | 产出 |
|---|---|---|
| 1 | 你怎么称呼？希望我怎么称呼你？ | 称呼 |
| 2 | 选一个人设（9 个卡片，带情绪价值标签） | persona_id |
| 3 | 想要什么样的主动消息？（频率滑杆 + 时段 + **内容偏向**） | heartbeat 参数 |
| 4 | 想让 TA 关注什么？（待办 / 倒计时 / **是否开启使用状态**） | 关注清单 |
| 5 | 权限授予（通知 → 后台 → 使用统计，逐个解释用途） | 权限状态 |
| 6 | 要不要接云端？（可选，可跳过） | API Key |

**产出：UserProfile**

```json
{
  "name": "主人",
  "persona": "catgirl",
  "heartbeat": { "interval_min": 10, "daily_cap": 100,
                 "quiet": ["23:30","07:30"], "bias": "balanced" },
  "watch": { "countdowns": [{"label":"小林生日","date":"2026-10-30"}] },
  "use_usage_stats": false,
  "cloud_key_set": false
}
```

**心跳的所有细节都从这里读**——这正是"摸清楚后再设定"。

## 8. 心跳与会话的连贯性（**改架构**）

### 8.1 当前问题

心跳只发**通知**，不写入会话：
- 用户点开 App，**看不到**刚才那条心跳消息
- 用户回复"嗯"时，模型不知道自己在说什么
- 消息**断裂**

### 8.2 目标

```
通知栏：🌙 绫 · 今天回来得比平时晚，还好吗？
          ↓ 点击
会话窗：🌙 绫：今天回来得比平时晚，还好吗？   ← 在上下文里
用户：  有点累
🌙 绫：辛苦了。要不要先歇一会儿？         ← 知道前因
```

### 8.3 技术前提：会话历史必须持久化

现在 `messages` 是**内存列表**，App 一关就没。要实现连贯必须：
1. 会话消息落库（Room / SQLite）
2. 心跳消息以 `source=heartbeat` 写入
3. 下次对话带上这些历史

**→ 这就是 M6，所以 M6 必须最先做。**

## 12. 采纳的补充想法（全部同意，逐条落地方案）

| 想法 | 实现方式 | 依赖 | 归入 |
|---|---|---|---|
| **每日简报** | 早 8:00 一条，聚合：**今日待办 + 倒计时 + 星期**（无新闻/天气，纯本地） | 无 | M9 |
| **周报** | 每周日 20:00 汇总：本周完成待办数、聊了几天、连续使用天数 | 会话持久化（M6） | M9 |
| **久坐提醒** | 连续使用 > 2 小时提醒 | UsageStats（默认关） | M12 |
| **重要日期倒计时** | 用户配置日期，提前 N 天提醒 | 无 | M9 |
| **一键静默「我今天不想说话」** | 通知栏 action + 应用内按钮，静默到次日 0 点 | 无 | M9 |

### 12.1 每日简报的具体格式（纯本地版）

```
☀️ 小满 · 早上好！
今天 10 月 18 日 星期日，有 3 件待办：
· 15:30 开会
· 买猫粮
· 交周报
还有 3 天是小林的生日 🎂
```

聚合了：问候 + 日期 + 待办 + 倒计时。**一条消息覆盖四个信息需求。**

### 12.2 一键静默的设计（重点）

- **通知栏 action**：每条心跳通知带一个「今天别说了」按钮
- **应用内**：设置页一个开关「今天不想说话」
- **行为**：静默到次日 0 点，自动恢复；界面显示"已静默到今天结束"
- **理由**：**给用户一个随时闭嘴的按钮，比任何精细算法都更尊重人**

| 项 | 设计 |
|---|---|
| 会话消息表 | `messages(id, role, content, source(local/user/heartbeat/cloud), created_at, conversation_id)` |
| 事实表 | `facts(id, key, value, updated_at)` — 记住"用户叫什么""不吃香菜" |
| 偏好表 | `prefs(key, value)` — 或直接用现有 SharedPreferences |
| 检索 | FTS5 全文检索（Room 支持 `contentEntity`） |
| 注入 | 每轮最多注入 500 token 相关记忆（预算感知） |
| 心跳写入 | 心跳消息以 `source=heartbeat` 落库 → 通知与会话同步 |

做完 M6，你说的"心跳消息在会话框里同步、形成连贯消息"就能实现了。

## 14. 工具层扩展：向"类 Hermes 系统"靠拢

### 14.1 Hermes 有什么，我们有什么

| Hermes 的构成 | 我们 | 说明 |
|---|---|---|
| **工具层**（tools + registry，插件化） | 🔶 有雏形（`Tool` 接口 + `ToolRegistry`） | **本章要升级的部分** |
| **记忆**（memory provider + 会话持久化 + 压缩） | ⬜ M6 | |
| **调度**（heartbeat + cron） | ✅ 有 heartbeat | cron 未做 |
| **人格**（SOUL + skills） | ✅ 8 人设 + 后处理 | skills（可复用过程）未做 |
| **模型路由**（smart routing） | ⬜ M10 | |
| **安全**（constitution + 拦截） | ✅ Tier-1/2 | |
| **子代理 / 网关 / 插件市场** | ❌ 暂无 | 当前不需要 |

**结论**：架构方向是对的，**缺的是"工具层要可插拔"这条规范**。

### 14.2 工具接口升级

现在：
```kotlin
interface Tool {
    val name: String
    val description: String
    val parametersJson: String
    fun execute(context: Context, args: JSONObject): String
}
```

升级为（对齐 Hermes 的 `tools/registry` 思路）：
```kotlin
interface Tool {
    val name: String
    val description: String
    val parametersJson: String

    /** 分类，用于设置页分组与按意图裁剪工具清单 */
    val category: ToolCategory get() = ToolCategory.GENERAL
    /** 是否联网（联网工具受"允许联网"总开关约束） */
    val requiresNetwork: Boolean get() = false
    /** 是否默认启用 */
    val enabledByDefault: Boolean get() = true
    /** 超时（联网工具要长一些） */
    val timeoutMs: Long get() = 15_000

    fun execute(context: Context, args: JSONObject): String
}

enum class ToolCategory { GENERAL, TODO, ALARM, NETWORK, TIME }
```

`ToolRegistry` 的职责：
- 按设置过滤（`enabled` + 联网总开关）
- 只把**启用的**工具交给模型（减少 prompt 体积 —— 这点很重要：工具越多，prefill 越慢）
- 分组展示给设置页

### 14.3 搜索工具 `web_search`

```
参数：query (string), count (int, 默认 5)
实现：DuckDuckGoHtmlProvider → GET https://html.duckduckgo.com/html/?q=<urlencoded>
       Jsoup 解析 .result__a（标题+链接）、.result__snippet（摘要）
返回：前 N 条 → 标题 / URL / 摘要
缓存：同一 query 10 分钟内复用，避免被判滥用
```

模型会这样用：
> 用户："帮我查一下今天 AI 圈的新闻"
> → `web_search("AI 新闻 今天")` → 拿回 5 条标题摘要 → 组织成人设口吻回答

### 14.4 行情工具 `market_quote`

```
参数：symbols (string, 逗号分隔，如 "sh600519,sh601398,USDCNY")
实现：SinaQuoteProvider → GET https://hq.sinajs.cn/list=<symbols>
       必须带 Referer: https://finance.sina.com.cn
       解析 var hq_str_sh600519="名称,今开,昨收,现价,...";
     失败时回退 TencentQuoteProvider
返回：每条 → 名称 / 现价 / 涨跌幅 / 时间
缓存：1 分钟
```

模型用法：
> 用户："茅台现在多少钱"
> → `market_quote("sh600519")` → "贵州茅台 1680.00（+3.2%）"

### 14.5 工具管理界面（设置页新增分区）

```
工具管理
├── [✓] 待办（3 个工具）
├── [✓] 闹钟
├── [✓] 时间
├── [ ] 联网搜索      ← 默认关，开启时提示"会访问 duckduckgo.com"
└── [ ] 行情查询      ← 默认关，开启时提示"会访问 sina.com.cn"

[ ] 允许联网（总开关，默认关）
```

**为什么要"按需启用"**：工具清单会进 prompt。20 个工具的 schema 约 2000 token，
每次 prefill 都要算——手机上这很贵（实测 4B 约 30–35 t/s，2000 token ≈ 60 秒）。
**只把启用的工具给模型是必须的**。

### 14.6 与心跳的联动（这才是搜索/行情的真正价值）

| 心跳触发源 | 依赖 |
|---|---|
| **行情异动**（±3% / 到目标价） | `market_quote` + 用户配置的关注列表 |
| **关注关键词新闻** | `web_search` + 用户配置的关键词 |
| **每日简报**（待办 + 倒计时 + **关注新闻摘要**） | 两者都用 |

**异动判断放在心跳服务里**（不在聊天里）：
```
每 30 分钟（可配）：
  拉行情 → 判断涨跌幅是否超阈值
    是 → 聚合进下一次心跳
    否 → 静默（不打扰）
```

### 14.7 安全与隐私

| 项 | 要求 |
|---|---|
| 联网总开关 | **默认关**，设置页显式开启 |
| 每类工具开关 | 独立开关，说明会访问哪个域名 |
| 请求内容 | 只发用户明确要求的内容（query / symbol），**不发会话上下文** |
| 结果缓存 | 本地缓存，避免重复请求 |
| 数据来源标注 | 回答里注明"数据来源：新浪财经 / DuckDuckGo" |
| 合规提示 | 行情"仅供参考，不构成投资建议" |
