# 实施计划（2026-10-21）

> 依据：《项目状态-2026-10-21》。本文把「文档收口 → 真机收尾 → 三个新人设 → 通讯录 → 自定义人设 → 群聊 → 朋友圈」拆成有门禁的阶段。
> 原则：**先检查、再动手；一步一验，验证不过不进下一步；不在本计划范围内的事不做。**

## 一、门禁机制

每个阶段都必须走完四件事：

1. **进入检查**：依赖是否满足（设备、拍板、上阶段证据、自检全绿）。不满足就停，不开工。
2. **实施**：只做本阶段列出的改动；发现新问题先记录，不顺手扩范围。
3. **出口检查**：按本阶段「验证」逐条跑命令，结果写入 `run\plan\`（文本/截图），并与「通过标准」比对。
4. **记录**：更新本文 §九 进度与《项目状态》证据表；不通过则写清失败原因，修好重跑，仍不过就停。

通用规则（沿用项目既有硬性要求）：

- 改代码前先补回归用例（`AssistantSelfTest` 或纯逻辑测试）；先红灯，再修，再绿灯。
- 每阶段结束跑全量自检；`persona-golden.ps1` 只允许「新增人设带来的新增行」，旧人设文本不得变化。
- 部署一律 `install -r`，**绝不卸载**；测试数据用调试钩子创建并在结束时清理。
- 证据不靠自述：编译输出、自检结果、e2e 结果、`uiautomator dump`、截图、日志文件。

### P2.2 三个包

按《会话交接》§27.2 的步骤与《心跳与双模型优化方案》§1 的设计：

- `PackAling.kt`（烂梗王·阿冷）：签名梗、毒舌但不攻击、情绪低落禁用玩笑；

台词规则：不带数字或中文数量词；数字只用槽位；逐条过 `InsultGuard`；树洞类红线（如深泽不承诺真实关系）写进提示词 + 守卫。

## 七、P4–P6（摘要，待前序通过后细化）

- **P4 自定义人设**：`custom_personas.json`；表单（类型名/名字/自称/性格一句话/口癖/造型）；从最接近的内置包克隆并替换名字，套模板生成回执/问答/心跳/专注台词；`validate` 不过不让保存；内置只能隐藏、自定义可删；删除时询问是否删聊天记录。红线：不自由写系统提示、长度限制、`InsultGuard`、固定在 `CAPABILITY_RULES` 之下。

- **P6 朋友圈模板**：`moments.json`；每人每天 1–2 条，内容只来自程序事实（时间/天气/专注/待办），套人设模板；点赞/评论；评论后下一次打开由模板回一句，不实时推理；界面标注「她们的动态」。
