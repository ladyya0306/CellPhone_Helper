# 共享节拍图与透镜（2026-10-22）

> 决定：不再给 14 个人设各写 360 天话术。改成 **1 张共享话题/节拍图 + 14 张人设透镜 + 1 个渲染器 + 1 套世界状态**。
> 下一步：**L1 = 20 个共享节拍 × 3 个人设透镜（小咪/零/傅沉）× 10 天 × 4 轮**，PC 对照测试。

## 一、为什么改

14 人 × 360 天 = 5,040 个“人设日”；手写是 5,040 套脚本。  
但聊天不是 5,040 个孤立句子，而是**同一批生活/社交节拍，由不同人用不同立场说出来**。

- 共享：节拍、话语行为、前置条件、效果、世界事实；
- 每人一张：立场、知识、目标、秘密、道具、口癖、边界；
- 渲染：模板/小模型只负责“把事实说成她”；
- 状态：话题栈、未闭合问题、承诺、belief、关系、剧情旗标。

## 二、三层架构

```text
WorldState（时间/天气/事件/事实）
  ↓
DialogueState（话题栈/未闭合问题/承诺/情绪/风格）
  ↓
BeatGraph（共享：节点=对话节拍，不是主题词）
  ├─ speechAct：问/答/安慰/调侃/拒绝/转移/收束
  ├─ requires：用户意图/关系/剧情/时间
  ├─ effects：关系/记忆/旗标/open_loop
  └─ roles：谁适合说、谁只能旁观
  ↓
PersonaLens（14 张）
  ├─ stance：她怎么看这件事
  ├─ knowledge：她知道/不知道
  ├─ goals/secrets/props/taboos
  └─ voice DNA
  ↓
Renderer（模板 / 小模型）
  ↓
Guard（事实/重复/安全/人设/长度）
```

数据：

```kotlin
data class BeatNode(
    val id: String, val domain: String, val speechAct: String,
    val requires: List<String>, val effects: List<String>,
    val roleTags: List<String>, val slots: List<String>
)
data class PersonaLens(
    val personaId: String, val stance: String,
    val knows: List<String>, val doesntKnow: List<String>,
    val goals: List<String>, val props: List<String>,
    val voice: String, val taboos: List<String>
)
```

## 三、20 个共享节拍（L1 骨架）

| id | 节拍 | 话语行为 | 前置/效果 |

| B07 | 安慰对方 | 安慰 | 用户低落；不急于给方案 |
| B08 | 用户没空/拒绝 | 接受拒绝 | 用户拒绝；不追问、不施压 |
| B09 | 小邀约 | 邀请 | 关系够/场景合适；生成 open_loop |
| B10 | 拒绝邀约 | 拒绝 | 有边界；给出替代/收束 |
| B11 | 用户迟到/失约 | 表达不满 | 用户失约；不升级攻击 |
| B12 | 道歉/和好 | 修复 | 有过冲突；降低紧张 |
| B13 | 分享小事件 | 分享 | 有 event；只讲一件 |
| B14 | 用户夸奖 | 接受夸奖 | 用户夸；按人设反应 |
| B15 | 被夸后的反应 | 害羞/傲娇/淡定 | 不统一卖萌 |
| B16 | 用户批评/误会 | 防御/澄清 | 有误会；不否定用户 |

| B20 | 未闭合问题/承诺 | 承诺/待办 | 用户提过带时间的事；写 future_beats |

> B01–B20 是 L1 骨架，不是 360 天全部内容；通过后再扩到 80–120 个节拍。

## 四、3 张人设透镜（L1）

| 透镜 | 小咪 | 零 | 傅沉 |
|---|---|---|---|
| 角色位 | 被照顾/黏人 | 低能量/极简 | 高位/决策 |
| 看同一件事 | 身体先反应：耳朵/尾巴/纸箱 | 先给结论：行/不行/明天 | 先判断：解决/放下/时间 |
| 知识 | 猫咖、纸箱、小鱼干、打雷 | 代码、多肉、黑咖啡、效率 | 公司、跑步、失眠、合同 |
| 不知道 | 公司政治、投资 | 猫咖内部、甜点 | 猫咖、二次元 |
| 目标 | 被关注、守住纸箱 | 少麻烦、把事情做完 | 控制风险、留余地 |
| 禁忌 | 不被当宠物使唤、不讨论成人 | 不情绪索取、不啰嗦 | 不解释第二遍、不命令用户 |
| 口吻 | 5–18 字、身体细节、喵有预算 | 2–12 字、省略号、术语 | 2–15 字、陈述、行动 |

同一节拍 B06（用户说累）的三种说法：

- 小咪：“（耳朵垂下来）主人今天走了好多路吗？小咪把窗台让给你。”
- 零：“嗯。先睡。代码明天再改。”
- 傅沉：“休息。明天再说。”

同一节拍 B10（拒绝邀约）：

- 小咪：“今天不行喵……纸箱还没搭好，明天陪你。”
- 零：“今天不。明天。”
- 傅沉：“不去。改天。”

**不是三套 360 天剧本，是同一骨架的三张透镜。**

## 五、DialogueState / WorldState

```text
WorldState: day, weather, events, facts
DialogueState:
  topic_stack: [meal, work, ...]
  open_loops: [{what, due, personaId}]
  commitments: [...]
  beliefs: {personaId: facts they know}
  relationship: affinity/trust/tension
  style_mode: NORMAL/TVB/...
  recent_topics: last 30
```

规则：

- 用户问题未回答前，不主动切话题；
- 切话题必须走 B18 桥接；
- 同一事实只由知道的人说；不知道就承认不知道；
- 承诺写 `open_loops`，下次由程序接，不靠模型记。

## 六、L1 对照测试（A/B/C）

### 三组

| 组 | 架构 | 人设 | 语料 | 轮数 |
|---|---|---|---|---|
| **A 基线** | 旧：直接 LifeCard + 人设提示词，无节拍图/无透镜/无状态机 | 小咪 | **小咪 360 天语料**（取前 10 天） | 40 |
| **B 新架构** | 新：共享节拍图 + 小咪透镜 + DialogueState + Renderer | 小咪 | **同一份 360 天语料前 10 天** | 40 |
| **C 复用验证** | 新：同一节拍图 + 零/傅沉透镜 + 状态机 | 零、傅沉 | 各自生活卡，同一世界事件 | 80 |
| 合计 | — | — | — | **160 轮** |

A/B 是主对比；C 只验证“换透镜能不能复用、会不会串味”，不和 A 比。

### 控制变量（A/B 必须相同）

- 同一 10 天、同一天气/世界事件；
- 同一份小咪 LifeCard 事实；
- 同一用户 4 轮脚本：问吃饭 → 追问 → 和谁/情绪 → 收束；
- 同一模型 Qwen3.5-4B、同一温度、同一 4 轮历史；
- 唯一差异：A 无节拍图/透镜/状态机；B 有。

### 评估

| 指标 | 门禁 | 对比方式 |
|---|---|---|
| 精确重复 | 0 | A/B/C 各自 |
| >40 字 | ≤5% | A/B/C |
| 上下文矛盾 | 0（人工复核） | A/B 主对比 |
| 编造用户事实 | 0 | A/B 主对比 |
| 编造“和谁” | 0 | A/B 主对比 |
| 口吻标记命中 | 每人 ≥80% | A/B/C |
| 跑题/答非所问 | ≤10% | A/B 主对比 |
| 跨人设串味 | 0（人工抽检 30 条） | B/C |
| 三人可区分度 | ≥80%（盲评） | B/C |
| 人工“像她” | ≥4/5 | A/B/C |
| 盲评偏好 | B 不差于 A（允许持平） | A/B 盲评 |

**通过条件**：

1. A/B 都过硬门禁；
2. B 在“上下文矛盾/编造/跑题”三项上 ≤ A；
3. B 的人工偏好不低于 A（允许持平，不允许明显更难读）；
4. B/C 三人可区分 ≥80%、串味 0；
5. 任一项不过，先改节拍/透镜，不扩 14 人。

## 七、复用与边界

| 层 | 复用性 |
|---|---|
| 引擎/状态/守卫 | 100% |
| 通用节拍（吃饭/累/邀约/拒绝/误会） | 60–80% |
| 人设透镜 | 每人 1 张，不可复用 |
| 专属节拍（猫咖/公司/琴房） | 按角色挂载，不硬套 |
| 风格模式 | 模式可复用；效果按人设 |

**不能把 14 人硬塞进同一话题**：每个节拍有 `roleTags` 与 `eligible`，只让合适的人说。

## 九、风险

- 节拍太抽象 → 14 人说出来像同一个模板；
- 透镜太弱 → 只剩口癖，没有立场；
- 状态不共享 → 多轮/跨人设矛盾；
- 风格切换盖掉人设；
- 以为“共享”=“所有话题都能给所有人”。  
  对策：每轮人工抽检 + 角色位校验 + 专属节拍白名单。
