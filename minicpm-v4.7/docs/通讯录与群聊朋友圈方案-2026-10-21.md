# 通讯录 · 增删人设 · 群聊 · 朋友圈 方案（步骤 1 已实施，其余待确认）

> 2026-10-21 更新：**步骤 1（阿冷 / 深泽 / 傅沉三个内置人设 + 红线）已实施**，见《项目状态》§2.1 与《实施计划》P2；其余步骤仍待拍板。

日期：2026-10-21。背景：用户希望界面更像微信——人设都是「朋友」，放进通讯录；可以增删人设；并评估能否拉群、发朋友圈。
前置事实（来自现有代码与实测）：
- 人设 = 数据（`PersonaPack`，一个 `Pack<Xxx>.kt`），`PersonaPacks.validate` 逐项把关；已支持改名与头像造型表 `AvatarLooks`。
- 会话已经按人设隔离（`Conversations`，换人设 = 开新会话，旧会话在「历史会话」里）；树洞 `privateSpace` 不进用户层记忆。
- 手机上同一时刻只有一个模型在推理，Qwen3.5-4B 每轮约 7 秒（`CAPABILITY_RULES` 注释里的实测），回复上限约 80 字。
- 之前设计过、从未加入的三个人设：**烂梗王·阿冷、乙女向·深泽、霸道总裁·傅沉**（`心跳与双模型优化方案.md` §1，每个都带程序红线）。病娇按既定决定不做。

## 一、通讯录（微信式联系人）

**做什么**：主界面第一屏改为「通讯录」：每个人设一行（头像 + 名字 + 最后一句话 + 时间 + 未读红点），点进去就是和她的聊天；右上角「+」添加人设、长按删除/置顶/改名。底部两个标签：「聊天」（按最近消息排序的会话列表）、「通讯录」（全部联系人按类型分组）。

**方案**：
- 现有 `MainActivity` 的聊天页保留，改成「某个联系人的聊天页」（intent 带 personaId）；新增 `ContactsActivity` 为入口（启动页）。
- 每个联系人固定对应「她的当前会话」（沿用 `Conversations`，不再需要「切换人设」概念，设置里的单选人设改为「默认联系人」）。
- 列表数据直接来自 `MemoryStore.listConversations` + 人设表，无需新表；未读数 = 她的心跳消息中比「上次打开时间」新的条数（新增一个 SharedPreferences 字段）。
- 头像、主题色沿用本次已做的 `AvatarView`/`Skin`；聊天页顶栏的表情状态不变。

**耗时**：1.5–2 天（含自检：联系人排序、未读计数、置顶、导航）。
**风险**：①心跳/专注/通知目前都按「当前人设」取话术，需要改成「谁发的就用谁的」——心跳要决定**由哪个联系人开口**（建议：由「默认联系人」开口，其余联系人只在用户点进去时说话，避免 8 个人同时骚扰）；②专注模式的监督官需要可选（默认用默认联系人）；③旧的单选人设入口要兼容，避免老用户困惑。

## 二、增加/删除人设

**分两层，难度差很大**：

1. **加入三个设计好的内置人设（阿冷、深泽、傅沉）**——低风险，0.5–1 天。按 `会话交接 §27.2` 的步骤：三个 `Pack<Xxx>.kt`（话术、回执、问答、心跳话术池、专注台词，全过 `validate`/`InsultGuard`）+ `AvatarLooks` 三套造型 + 自检。红线程序化：阿冷「情绪低落禁用玩笑」走现有痛苦信号闸门；深泽「不承诺真实关系」、傅沉「不下命令」用 `ClaimGuard` 加规则 + 评测脚本 `companion-eval.py` 抽检。
2. **用户自己创建人设**（表单：类型名、名字、自称、称呼、性格描述、口头禅、头像造型从预设里选）——中风险，2–3 天。
   - 用户只填「性格一句话 + 口头禅」，其余话术（回执、问答、心跳、专注台词）**不让用户写**，而是**套模板**：从最接近的内置人设克隆（例如选「像小咪那样」），把名字和口癖替换进去，保证 `validate` 通过、专注台词不带脏话。
   - 存储：`custom_personas.json`，启动时与 `PersonaPacks.ALL` 合并（`ALL` 由常量改为「内置 + 自定义」）；删除只允许删自定义的，内置的只能「隐藏」（通讯录里不显示）。
   - 删除联系人 = 询问是否同时删除聊天记录；记忆里该人设写入的用户层事实保留（那是用户自己的信息）。

**风险**：①用户随手写的「性格」直接进系统提示 = 提示词注入/越界内容（如要求她骂人、扮演真人）——必须过 `InsultGuard` + 长度限制 + 固定在 `CAPABILITY_RULES` 之下（能力边界对所有人设恒定，已满足）；②自定义人设的口吻差异化无法评测，质量不如手写，建议在界面里写明「克隆自 XX」；③`validate` 里的签名词（signature）要求自定义人设也有，克隆时自动继承并替换。

## 三、群聊

**能不能做：能，但必须是「轮流发言」而不是真并行。**

模型一次只能生成一条，所以群里 N 个人回一条消息 = N 次推理 ≈ N × 7 秒。体验取决于怎么裁剪：

| 方案 | 机制 | 耗时/体验 | 评价 |
|---|---|---|---|
| **A 被点名才答（推荐首版）** | 用户 @谁谁答；没 @ 则由「话题最相关的 1 人」答（程序按关键词/人设标签路由，不用模型） | 与单聊相同，约 7 秒 | 最稳，几乎无新风险 |
| B 轮流各说一句 | 用户发言后，群成员按固定顺序各回一句（≤40 字，限 3 人） | 3 人约 20 秒，边出边显示 | 有「热闹」感，但慢，要显示「正在输入…」 |
| C 她们互相接话 | 一个人说完，另一个接着回应（多轮） | 不可控、容易跑题互骂 | **不建议**：4B 模型易跑偏、复读、人设串味（评测里已见到傲娇串成病娇的先例） |

**共同设计**：
- 群 = 一个会话（`persona_id = "group:<id>"`），消息表加 `speaker_id` 列；每个人设发言时，**系统提示只放她自己的人设**，上下文里把别人的话标成「【小咪】……」，避免角色串味（这是 `§27.3` 评测发现的最大风险）。
- 树洞（`privateSpace`）**禁止入群**，红线。
- 用户记忆：群聊内容仍只写用户层事实一次，不因 N 个人听到而重复记 N 遍。
- 群里闹钟/提醒这类动作只由被 @ 的那位执行，回执仍来自动作账本（不变量不变）。
- 提示词长度：每次推理上下文含最近 N 条群消息，手机上下文 2048，限制最近 8 条。

**耗时**：方案 A 约 2 天；加 B 再 2 天（含「正在输入」状态、气泡带说话人头像与名字、自检路由）。
**风险**：①速度（见上）；②角色串味（必须评测：8 人设×群场景，扩展 `companion-eval.py`）；③后台冻结：这台 vivo 退后台约 20 秒就冻结，多人轮流发言时用户切走会中断（沿用 `AssistantRuntime` 在后台跑完一轮，但多轮要逐轮续跑）。

## 四、朋友圈

**能不能做：能做成「她们各自发动态」，但只能是低成本的离线版本。**

**机制（推荐）**：
- 每个联系人每天最多 1–2 条动态，来源有两类：①**程序模板**（按时间/天气/用户今天的待办完成情况合成事实，再套各人设口吻——和现在的心跳话术池同一套路径，不调用模型，零延迟）；②**可选**：模型在充电+熄屏时批量生成 1 句短感想（沿用 F3 批量生成台词库的思路，过 `InsultGuard`/`ReplyCleaner`/`ClaimGuard` 才入库）。
- 用户可以点赞、评论；评论后该联系人在**下一次**用户打开时回复一句（不实时推理，避免卡）。
- 事实只来自程序：「今天下雨」要有天气数据支撑，「陪你专注了 25 分钟」要有专注记录支撑，不允许编造（沿用 `ClaimGuard` 编造类规则）。
- 存储：`moments.json`（作者、时间、文本、点赞、评论），列表页复用头像组件，进入「发现」标签。

**耗时**：纯模板版 2 天；加批量生成与评论回复再 1.5 天。
**风险**：①最容易做成「模型编的假生活」（评测里已出现「编造自己做过的事」9 条）——所以首版不用模型，只用事实模板；②动态内容太单薄会显得假——需要为每个人设写足够多模板（现有话术池可复用）；③不要和用户的真实朋友圈混淆，界面标注「她们的动态」；④耗电：批量生成只在充电熄屏时跑。

## 五、建议的实施顺序与里程碑

| 步骤 | 内容 | 耗时 | 依赖 |
|---|---|---|---|
| 0 | 修「改名弹窗深色」小问题并重新部署（源码已改，待编译/部署/截图） | 0.5 小时 | 无 |
| 1 | 加入阿冷、深泽、傅沉三个内置人设（含红线、造型、自检、评测） | 0.5–1 天 | 无 |
| 2 | 通讯录（联系人列表 + 每人一个会话 + 未读 + 置顶），心跳由「默认联系人」开口 | 1.5–2 天 | 步骤 1 可并行 |
| 3 | 增删自定义人设（克隆模板 + 表单 + 校验 + 隐藏内置） | 2–3 天 | 步骤 2 |
| 4 | 群聊方案 A（@ 或路由，单人回答）；再评估 B | 2 天（+2） | 步骤 2、3 |
| 5 | 朋友圈模板版；再评估模型批量生成 | 2 天（+1.5） | 步骤 2 |

每一步都沿用现有规矩：先补用例再改、自检全绿、`persona-golden.ps1` 只多不改、部署后 `uiautomator dump` 巡检并截图。

## 六、需要你拍板的事

1. 通讯录里**谁来主动开口**（心跳/晨报晚报）：只由默认联系人？还是每个联系人各有开关、默认只开一个？（推荐前者，避免被 8 个人刷屏）
2. 自定义人设允许写到什么程度：**克隆模板 + 改性格/口癖**（推荐），还是允许完全自由写提示词（风险高，需要额外审核）？
3. 群聊首版：只做 **A 被点名才答**，还是直接要 **B 轮流发言**（慢、更热闹）？
4. 朋友圈首版：**纯事实模板**（推荐）还是一开始就加模型生成？
5. 三个新人设里的「霸道总裁」红线（不下命令、不贬低）要不要再收紧（比如不用「你必须/不许」）？
