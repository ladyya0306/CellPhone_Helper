# 方案：小秘书功能扩展 + 专注模式（草案 v0.1，待用户拍板）

> 2026-10-19 夜。本文只是方案，**没有写任何代码**。每一条能力标注了「已验证 / 待真机验证」，没验证的不当作事实。
> 沿用的铁律：程序说事实、模型说情绪；先补用例再做；每步附证据；离线优先，联网必须是用户明确打开的开关。

## 一、现状盘点（代码里真实有的）

| 类别 | 现有 | 缺口 |
|---|---|---|
| 工具 | 7 个：待办（加/列/完成）、闹钟、提醒、日历写入、当前时间 | 无"改/删/推迟"闹钟与提醒；无重复规则；无多事件批量录入 |
| 查询 | 记忆问答、世界问答（只回答"不知道"或查本机数据） | 天气、步数、用电、使用时长都没有 |
| 信息提取 | `FactExtractor`：**单句、≤60 字、整句锚定的正则**，只认"我叫/我喜欢/我不吃/我习惯/生日/以后叫我/记住" | 一段话里的时间/地点/人物/事件抽不出；兴趣、职业、家人、宠物、作息这类身份信息只靠固定句式 |
| 感知 | 电量、时间、系统闹钟、日历 | 不知道屏幕亮灭、在不在用手机、走了多少步、天气、是否在开会/睡觉 |
| 主动 | 心跳（模板，不开模型），有去重、免打扰、次数上限 | 心跳不"看场合"：不知道你在开会、在睡觉、在充电 |
| 人设 | 8 个，已有统一口吻规则 | 没有"游戏化"的长期机制 |

联网：manifest 声明了 `INTERNET`，**代码里没有任何网络调用**，目前是真正的离线应用。

## 二、手机能力清单（能调用什么、要什么权限、有什么坑）

分四档：**A 免权限**、**B 运行时授权**、**C 去系统设置里手动开**、**D 联网**、**E 不建议碰**。

### A. 免权限（可直接用）

| 能力 | API | 能干什么 | 状态 |
|---|---|---|---|
| 电量/充电状态 | `BatteryManager` | 已在用；"在充电+熄屏+夜里"≈睡觉的强信号 | 已用 |
| 屏幕亮灭、解锁 | 动态注册 `ACTION_SCREEN_ON/OFF`、`ACTION_USER_PRESENT`（清单里静态注册无效） | 专注模式的核心信号；"夜里还在亮屏" | 待真机验证（vivo 冻结下前台服务内注册能否稳定收到） |
| 网络类型 | `ConnectivityManager` | 判断能不能走联网功能 | 容易 |
| 勿扰/铃声模式 | `NotificationManager.currentInterruptionFilter`、`AudioManager.ringerMode` | 用户开了勿扰 → 心跳静默 | 待验证 |
| 通话中 | `AudioManager.mode == MODE_IN_CALL` | 通话时不弹、专注计时暂停（不用 `READ_PHONE_STATE`） | 待验证 |
| 手电筒 | `CameraManager.setTorchMode` | 小游戏/闹钟闪灯 | 容易 |
| 震动 | `Vibrator` | 专注警告分档震动 | 容易 |
| 离开本应用 | `Activity.onStop / onUserLeaveHint` | "不要离开本应用"的最基本检测，**完全不需要权限** | 容易 |
| 系统分享 / 桌面小组件 / 快捷方式 | 标准 API | 一键"加待办/开专注" | 容易 |

### B. 运行时授权（弹一次允许）

| 能力 | 权限 | 能干什么 | 备注 |
|---|---|---|---|
| **步数** | `ACTIVITY_RECOGNITION` + `Sensor.TYPE_STEP_COUNTER` | 今日步数、昨日步数、久坐 | 计步器是"自开机累计"，要自己存每日基线、处理重启清零；vivo 健康 App 没有公开接口，**不要依赖**。Health Connect 可读，但厂商不一定写入，待验证 |
| 粗略位置 | `ACCESS_COARSE_LOCATION` | 给天气用（只取城市级坐标） | 不做后台持续定位 |
| 联系人 | `READ_CONTACTS` | 联系人生日、人名消歧（"给小王打电话"→哪个小王） | 只读，不上传 |
| 日历（已有） | `READ/WRITE_CALENDAR` | 已用 | |
| 照片/视频 | `READ_MEDIA_IMAGES` | 配合 Qwen3-VL 的视觉能力识图 | 模型在手机上跑图片的耗时/内存**没测过**，先不承诺 |
| 麦克风 | `RECORD_AUDIO` | 语音输入 | 系统输入法自带语音输入已够用，**不优先** |

### C. 去系统设置里手动开（我不能替用户开，也不会引导绕过）

| 能力 | 入口 | 能干什么 | 备注 |
|---|---|---|---|
| **应用使用情况** | 设置 → 特殊权限 → 使用情况访问 | 当前前台应用、各应用使用时长 → 专注模式能识别"打开了抖音" | 数据不出本机；只在专注期间读；**不把应用名写进记忆** |
| 悬浮窗 | `SYSTEM_ALERT_WINDOW` | 更强的"弹窗盖住分心应用" | 打扰度高，默认不用，做成可选的"地狱难度" |
| 通知使用权 | `NotificationListenerService` | 读通知（感知"消息轰炸"） | 隐私很重，**默认不做** |
| 精确闹钟（已有） | | 已用 | |

### D. 联网（唯一建议开的口子：天气）

- 天气来源：免密钥的公开气象接口（如 Open-Meteo）。**只发送城市级经纬度（取整到 0.1°），不带任何用户标识**。
- 做成设置里的显式开关，默认关；文案写明"会向第三方气象服务发送你所在城市的大致坐标"。
- 无网/关闭/失败 → 程序直接说"我现在查不到天气"，**不让模型猜**（和已有"不编造"原则一致）。
- 缓存 1–3 小时；晨报、出门提醒、心跳共用一份缓存，避免反复请求。

### E. 不建议碰

无障碍服务（权限过大，且会让 App 像木马）、设备管理员/锁屏控制（专注模式不需要"强制"，强制会毁掉信任）、读短信/通话记录、后台持续定位、屏幕内容抓取。

## 三、信息提取：从一段话里抽出「时间、地点、人物、事情」和身份信息

### 3.1 为什么现在不行

`FactExtractor` 是整句正则，用户发"下周三下午两点跟李总在国贸星巴克聊合同，顺便帮我妈订周日的生日蛋糕"，当前系统什么也抽不出，也不会把它拆成两件事。

### 3.2 方案：四层，宁可漏，不可错

1. **规则层（程序，保留）**：时间由现有 `TimeParser` 解析（再补"下周三""月底""大后天上午"等）；已有的固定句式保持不变，作为高精度兜底。
2. **模型抽取层（新）**：用 llama.cpp 的 **GBNF 语法约束**让 Qwen3.5-4B 只能输出固定 JSON，如：
   ```json
   {"events":[{"what":"聊合同","when":"下周三 14:00","where":"国贸星巴克","who":["李总"]}],
    "profile":[{"type":"家人","text":"妈妈","evidence":"帮我妈订…"}]}
   ```
   异步执行：**回复用户之后**、`:llm` 空闲时再抽，不拖慢聊天；失败就丢弃，不重试刷屏。
3. **程序校验层（关键）**：抽出的每个字段必须**逐字（或归一化后）出现在原话里**，时间必须能被 `TimeParser` 解析成具体时刻，否则丢弃。这样模型最多"漏"，编造的内容进不了库——和 ClaimGuard 同一个思路。
4. **确认层**：
   - 事件 → 一条轻量确认："要我记成「下周三 14:00 国贸星巴克，跟李总聊合同」的提醒吗？"（点一下或回复"好"）。**不静默写日程**。
   - 身份信息（兴趣、职业、家人、宠物、作息）→ 先进「候选记忆」，同一信息出现 2 次或用户确认后才转正；每条都带"来源句 + 时间"，可在记忆页查看/编辑/删除。
   - **敏感类不自动记**：健康/疾病、财务、宗教、性取向、证件号、住址门牌；树洞人设永不写入用户层。

### 3.3 落地量与风险

- 要新增：`ExtractionSchema`（语法）、`ExtractionValidator`（纯 Kotlin，可单测）、候选记忆表、记忆管理页。
- 评测：用现有 `model-eval.py` 管线加"抽取题集"，指标 = 编造率（必须 0）、漏抽率、字段对齐率。**先在电脑上评，再上手机**。
- 风险：4B 模型在语法约束下的耗时（预计每次数秒，需实测）；多事件拆分的准确度。

## 四、不同因素组合出来的功能（按价值排序）

先说原则：**能力越多越要克制**。每个功能必须回答"用户为什么会觉得这是贴心而不是烦"。

| # | 功能 | 用到的因素 | 说明 |
|---|---|---|---|
| 1 | **智能免打扰** | 日历(会议中)、勿扰状态、充电+熄屏+夜里、通话中、专注中 | 不开口也是一种细节；现在的心跳"不看场合"，这是最先该补的 |
| 2 | **晨报** | 天气、今日日程、待办、下一个闹钟、昨日步数 | 起床后第一次亮屏，人设口吻一句话 + 一张卡片；内容全由程序给，模板组合 |
| 3 | **出门/带伞** | 天气(降雨概率)、日程地点、时间 | "下午 3 点有雨，你 2:30 的日程在国贸" |
| 4 | **睡前轻劝** | 作息记忆、屏幕亮屏时长、明早闹钟 | "明早 7:00 有闹钟，现在 0:20 了"；每晚最多 1 次，用户说"别劝"就当天停 |
| 5 | **提醒的"稍后/完成"** | 通知按钮 | 通知上加「完成 / 10 分钟后再提醒」，`snooze` 是秘书类 App 的基本功 |
| 6 | **一句话多事录入** | 3 的抽取层 | "明早 9 点开会，下午 3 点牙医，周五交报告" → 一次确认三条 |
| 7 | **运动/久坐** | 步数、时间、天气 | 下午步数 < 阈值且天气好 → 邀请散步；**只邀请，不打卡施压** |
| 8 | **周回顾** | 待办完成率、专注时长、步数、情绪（树洞除外） | 每周日一条，人设点评；全部数字来自账本 |
| 9 | **生日/纪念日** | 联系人生日、记忆事实 | 提前 3 天、当天各一次（已有"每日次数上限"保护） |
| 10 | **低电量+明早要用** | 电量、明早闹钟/日程 | "只剩 18%，明早 6:30 有闹钟，睡前充一下" |
| 11 | **剪贴板线索**（可选） | 剪贴板（仅前台可读） | 复制了取件码/日期，问是否加待办；默认关 |
| 12 | **语音朗读**（可选） | 系统 TTS | 离线 TTS 音色和人设不贴，**排后** |

### 细节打磨清单（"靠细节取胜"）

1. 提醒/闹钟：改时间、取消、重复规则（每周三、工作日）、批量取消。
2. 待办：截止日、优先级、"今天最重要的三件事"、完成时的一句人设庆祝（一天至多一次）。
3. 撤销："刚才那条删掉"——所有写入动作都能撤销，账本里已有基础。
4. 歧义就问一句，别猜（已有槽位补全，扩大覆盖）。
5. 回复长度/节奏：闲聊 1–3 句已定，补"夜里更短更轻"。
6. 所有"主动"内容都有三道闸：话题次数上限、同内容冷却、用户收口词（已做一部分，见交接文档十四节）。

## 五、专注模式（深度方案）

### 5.1 一句话

用户选一个人设当"监督官"，设定时长；程序负责**计时、检测、算生气值、定惩罚**，人设负责**把这些事实说得好笑、扎心、有性格**。像一个会生气的小游戏，但出口永远在用户手里。

### 5.2 架构：程序判、模型说、台词预生成

```
信号层 ──→ 规则引擎(程序) ──→ 生气值/档位/事件 ──→ 台词选择器 ──→ 通知/界面
 屏幕亮灭          事实槽位：离开 37 秒、第 3 次、       (预生成台词库
 离开本应用         生气值 72、剩余 12:30                 + 槽位填充)
 前台应用(可选)                                          ↑
 通话/勿扰(暂停)      空闲时由模型批量生成 → InsultGuard 审查 → 入库
```

- **为什么台词要预生成**：干扰发生时要立刻弹字。本地模型冷启动约 17 秒、一条约 3.5 秒，且 vivo 会冻结后台。所以：**专注开始前/空闲时**，让模型按「人设 × 档位 × 事件类型」批量生成台词，经审查入库；运行时程序**选台词 + 填数字**，不开模型、不耗电、不怕被冻结。
- 模型只在两处"现场"出场：回到前台时的一句收场白、结算点评。失败就用库里的。
- 事实槽位由程序填（几次、几秒、剩余时间、生气值），台词里的数字必须与槽位一致（沿用 ClaimGuard 的思路做校验）。

### 5.3 信号与权限（分三档，用户可选）

| 档位 | 能检测什么 | 权限 | 备注 |
|---|---|---|---|
| 基础 | 离开本应用、亮屏看手机 | **无** | 默认档，先做 |
| 进阶 | 具体打开了哪个分心应用、累计时长 | 使用情况访问（手动开） | 用户自选分心名单，数据不出本机 |
| 地狱 | 弹窗盖住分心应用 | 悬浮窗 | 可选，默认不开 |

- 宽限期：离开 8 秒内回来不扣分（看通知、切输入法不冤枉）。
- 白名单：通话自动暂停；用户可勾选"允许的应用"（如计算器、词典）。
- 亮屏弹信息：用高优先级通知（锁屏可见）。亮屏只在**专注计时期间**才监听，结束即注销。

### 5.4 生气值规则（先定数值，可调）

| 事件 | 生气值 |
|---|---|
| 离开本应用 | +15，之后每停留 10 秒再 +1 |
| 亮屏看手机（不在本应用） | +10 |
| 打开分心应用（进阶档） | +20 |
| 回到本应用 | −5（慢慢消气） |
| 连续 5 分钟无干扰 | −10（回血） |
| 档位 | 0–29 平静（鼓励）· 30–59 唠叨 · 60–89 阴阳怪气 · 90+ **爆** |

**爆了怎么办（惩罚）**：人设"冷战"——界面变灰、不再回复，只显示"已读不回"，持续 N 分钟（可选 2/3/5）；冷战期间计时继续，用户回到本应用安静待着可缩短冷战。冷战结束人设用一句和好的话开场。**惩罚只是游戏内的"不理你"，不锁手机、不阻止使用任何应用。**

### 5.5 骂人，但不带脏字（硬指标）

这件事要**用工程手段保证，而不是靠 prompt 祈祷**：

1. **修辞菜单**：生成时只允许 6 类手法——反语夸赞、夸张比喻、拟人化吐槽、文言腔、歇后语/俏皮话、"自嘲式连坐"（"连我都替你着急"）。给模型每类 few-shot。
2. **对象限定**：只能吐槽"这次的行为"，不得涉及外貌、身材、家人、地域、性别、疾病、智力等。
3. **InsultGuard（纯 Kotlin，可单测）**：脏话词表 + 谐音/拼音缩写/符号替代 + 人身攻击词表（"蠢/废物/智障"类一律否决）+ 长度与重复检查。**任何一条台词没过审就不入库**。
4. **离线评测**：用现有评测管线，指标 = 脏字率（硬指标 **0**）、人身攻击率（**0**）、人设贴合度、复读率（≤0.1）；通过才发布台词库。
5. **难度/尺度**：设置里「温和 / 毒舌 / 地狱」，默认毒舌。地狱档仍然受 InsultGuard 约束，区别只是密度和阴阳怪气程度。

台词风格示意（均为程序审查通过的那一类；**示意，非最终**）：
- 傲娇：「哼，才三分钟你就想跑？本小姐的耐心是有限额的，你已经透支 37 秒了。」
- 姐姐：「姐姐不凶你……只是在心里给你记了一笔，等会儿一起算。」
- buddy（毒舌）：「您这专注力，金鱼听了都想递张名片。」
- 冷娇：「数据：离开 3 次，累计 52 秒。结论：不及格。」
- 汪汪：「（用爪子拍你的手机）汪！不许看！我们说好的！」

### 5.6 安全阀（防止做成"伤害用户"的东西）

- 出口永远在：任何时刻一键"我要结束"，结束不扣分、不羞辱；退出台词是中性的。
- 用户说出痛苦词（沿用现有痛苦词表）或明显情绪低落 → **立刻降到温和档**，并停止骂人。
- 深夜（免打扰时段）不开地狱档；连续多次在同一时段失败 → 提议"今天先到这里"，而不是越骂越凶。
- 不记录分心应用名到长期记忆；统计只存"次数/秒数"。
- 台词里不出现"你真没用"这类攻击自我价值的话——由 InsultGuard 的人身攻击词表兜底。

### 5.7 游戏化（克制）

结算评级（S/A/B/C）、连续专注天数、人设称号（"今日劝退失败"）、本周专注总时长。**不做排行榜、不做社交分享**，避免变成压力。

### 5.8 里程碑与验收

| 阶段 | 内容 | 验收证据 |
|---|---|---|
| F1 | 计时 + 离开/亮屏检测 + 生气值引擎 + 预置少量台词（**无模型**） | 引擎自检用例全绿；真机：离开 40 秒后收到第一条通知、生气值日志写文件 |
| F2 | 进阶档：使用情况访问 + 分心应用名单 | 真机：打开测试应用被识别；关闭权限时降级到基础档 |
| F3 | 模型批量生成台词 + InsultGuard + 评测 | 评测报告：脏字率 0、人身攻击率 0、复读 ≤0.1 |
| F4 | 冷战惩罚 + 结算 + 统计 + 难度 | e2e：爆表 → 冷战 → 结束；`E2E_FOCUS` 调试钩子能 2 分钟内跑完整局 |
| F5 | 安全阀 + 深夜规则 + 退出 | 用例：痛苦词立即降档；一键退出不扣分 |

测试原则不变：**必须当场能出结果**——专注局的计时在调试包里可缩放（1 分钟代替 25 分钟）。

## 六、路线建议

1. **先补地基（1–2 周量级）**：智能免打扰、提醒 snooze/改/删/重复、一段话多事录入（抽取层）、候选记忆与记忆管理页。
2. **再上"有数据"的功能**：天气（联网开关）+ 步数 + 晨报 + 出门提醒。
3. **专注模式 F1→F5**：F1 不依赖模型和新权限，可与第 2 步并行启动。
4. 周回顾、剪贴板、语音朗读放最后。

## 七、需要用户拍板的事

1. 天气是否接受"可选联网"（只发城市级坐标，默认关）？
2. 专注模式首版是否只做「基础档」（无需任何权限）？进阶档的使用情况访问是否愿意手动开？
3. 骂人尺度：默认"毒舌"是否合适？"地狱档"要不要做？
4. 冷战惩罚时长默认值（建议 3 分钟）和宽限期（建议 8 秒）。
5. 信息提取：事件是否一律"先确认再写入"（建议是）？候选记忆"出现两次转正"的规则是否接受？
6. 从哪一块先动手（建议：智能免打扰 → 多事录入 → 专注 F1）。
