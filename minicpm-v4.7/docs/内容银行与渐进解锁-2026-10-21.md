# 内容银行与渐进解锁（2026-10-21 批准）

> 目标：让 14 个人设在 **6 个月**内不靠复读维持新鲜感；DeepSeek 离线生产内容，Qwen3.5-4B 只在会话里润色；好友从 1 个青梅竹马开始逐步解锁。
> 原则：程序说事实、模型说情绪；内容银行离线生成、手机端只读；审核比生成更重要。
> 风格源与版权边界见《[语料库与风格源](语料库与风格源-2026-10-21.md)》；七种 StyleMode 见《[风格模式与语料扩展](风格模式与语料扩展-2026-10-21.md)》；故事网络/多结局见《[故事网络与多结局](故事网络与多结局-2026-10-21.md)》。

## 一、决定

| 项 | 决定 |
|---|---|
| 内容生产 | **DeepSeek 离线预生成**内容银行；不用手机 4B 生产 |
| 会话润色 | Qwen3.5-4B 只做聊天/群聊接话/摘要润色 |
| 内容结构 | 模板 + 槽位 + 内容银行 + 叙事线 + 去重调度 |
| 目标周期 | **6 个月（180 天）**；2 个月和 6 个月存储几乎一样，审核量差 3 倍 |
| 好友 | 初始只解锁 1 个**青梅竹马**；其余 12 个按陪伴/话题/社交/故事逐步解锁 |
| 群聊 | 2–3 个 AI + 用户；不预设群；364 种组合；先 PC 拟真 |
| 审核 | 结构/声音/安全/新颖/人工五道关 + 180 天模拟 |

## 二、6 个月的量（文本很小）

| 内容 | 6 个月用量 | 存储估算 |
|---|---|---|
| 心跳 | 2 条/天 × 180 = 360/人设 | 14×360×50 字 ≈ 250KB |
| 私聊 LifeCard | 1 张/天 × 180 = 180/人设 | 14×180×80 字 ≈ 200KB |
| 专注 | 2 局/天 × 17 句 = 6,120/人设（不硬存） | 300 模板 + 槽位，约 4,200 条 ≈ 200KB |
| 朋友圈 | 1 条/天 × 180 = 180/人设 | 约 150KB |
| 群聊 | 200 方向 × 3 变体 + 每人 20 条开场 | 约 100KB |
| 回执/问答 | 每人 20–30 条 | 约 40KB |

**结论**：3 万条纯文本约 10–20MB；模型 2.6GB。存储不是瓶颈，**组合、审核、叙事才是**。

## 三、内容银行结构

```kotlin
data class ContentCell(
    val id: String,
    val personaId: String,
    val scene: Scene,        // HEARTBEAT_*, FOCUS_*, MOMENT_*, GROUP_*, RECEIPT, QA, UNLOCK, CHILDHOOD
    val tone: Tone,          // CALM / NAG / SNARK / HELL / WARM / COLD
    val stage: Stage,        // STRANGER / ACQUAINTANCE / FRIEND / CLOSE / CHILDHOOD
    val template: String,    // 含 {slot}
    val slots: List<SlotSpec>,
    val requires: List<String>, // 标签：raining / user_busy / chapter>=3 / group_size=3
    val weight: Int,
    val source: String,      // deepseek / human
    val review: String,      // pending / passed / rejected
    val examples: List<String>
)

data class SlotSpec(val name: String, val type: SlotType, val values: List<String>)
```

- 资产按 `assets/content/<persona>/<scene>.json` 分片，按需加载；不把 6 个月文本塞进代码。
- 只存**骨架 + 槽位值 + 少量成品样例**；运行时组合，不存所有排列。
- 每个格子必须有 `requires` 兼容规则，禁止“零在跑步、胡德贵在剪花”。

## 三·补、私人会话：日常循环（LifeCard）

私聊主打**陪伴**，不是故事推进；也不该用固定聊天台词，否则吃饭/运动/做事一周就复读。做法：

```kotlin
data class LifeCard(
    val day: Int, val weekday: String, val weather: String,
    val breakfast: String, val lunch: String, val dinner: String, val snack: String?,
    val exercise: String, val work: String, val smallEvent: String,
    val mood: String, val energy: String, val hook: String,
    val props: List<String>   // 纸箱/多肉/琴房等，来自小传
)
```

- 每人设每天 1 张；程序从牌堆组合，不调模型；
- 牌堆：吃饭（早/午/晚/加餐）各 12–20 个变体；运动 20；做事/差事 20；小事件 30；心情 8；精力 5；天气 6；
- 模型只拿“今天的 LifeCard + 最近 7 天聊过什么 + 用户原话”，把它说成像她；
- 最近 30 天话题/最近 50 句做冷却；同一话题不连续两天出现；
- 私聊可以完全不提故事；用户想聊什么就聊什么。

**为什么不是“聊天语料库”**：6 个月的聊天是无穷的；固定回复一定会重复。可复用的是“她今天的生活状态/话题钩子”，不是“她必须说的句子”。

## 四、槽位（随机变量）

| 类别 | 变量 |
|---|---|
| 时间 | 早/午/晚/夜、工作日/周末、季节、节日、节气 |
| 环境 | 晴/雨/冷/热、电量、充电/熄屏 |
| 用户 | 忙/累/开心/焦虑/生病/加班/旅行/考试/面试 |
| 关系 | 认识天数、亲密度、解锁阶段、上次互动 |
| 故事 | 当前章节、当前目标、秘密、未完成事件 |
| 人设道具 | 小咪的纸箱、绫的书、零的多肉、傅沉的表、胡德贵的体检报告…… |
| 群聊 | 成员组合、关系、上一位发言者、当前话题 |
| 记忆 | 最近会话摘要、长期事实、朋友圈/群事件 |

规则：**事实槽位只能来自程序**（时间/天气/待办/用户原话/账本）；虚构槽位只能来自小传（道具/地点/章节），不能编用户现实。

## 五、叙事线

- 每人设 **12 章 × 6 节 × 3 变体** = 216 个故事节拍；一天 1 节可撑 7 个月。
- 章节示例：初识 → 熟悉 → 一次冲突 → 和好 → 共同目标 → 秘密 → 低谷 → 重新开始……
- 节日/季节事件独立池：春节/中秋/生日/考试季/梅雨/初雪等。
- 朋友圈、群聊、心跳共用“当前章节”，不会各说各的。

## 六、渐进解锁

### 6.1 初始

- 用户从 **13 个非树洞人设**中选 1 个做青梅竹马（树洞保持私密，不参与）。
- 青梅竹马覆盖层：8 段童年记忆、专属称呼、3 个特殊场景；成年性格保留，只多一层“你们小时候就认识”。
- 其余 12 人初始为 `STRANGER`（通讯录显示剪影 + “还没认识”），不生成假对话。

### 6.2 阶段

`STRANGER → ACQUAINTANCE → FRIEND → CLOSE`；青梅竹马直接从 `CHILDHOOD` 开始。

### 6.3 解锁条件（程序判定）

任一组合达到阈值即可，不靠模型：

1. **陪伴**：认识 3/7/14/30/60/90 天；
2. **话题**：工作→胡德贵/傅沉/沈砚；健身→陈野；音乐→凛；宠物→阿壹；书→绫；代码→零；
3. **社交**：和已解锁的人在群里聊过、朋友圈互动过；
4. **故事**：帮她完成一件事/到达章节节点。

### 6.4 节奏

- 全局最多 **每 3 天解锁 1 人**；自然节奏约 1–2 周 1 人，13 人约 6 个月。
- 必须用户点“认识一下”才加入；可拒绝/延后，不自动加好友。
- 解锁时给一张“新朋友卡”（小传一句话 + 关系），不打断聊天。

## 七、DeepSeek 生产流水线

1. 输入：人设圣经卡 + 场景矩阵 + 槽位表 + 禁止项 + 已有内容（去重）。
2. DeepSeek 每格生成 10–20 个候选，输出 JSONL。
3. 自动审核（见 §八），保留 4–6 个/格。
4. 人工抽检 10%，不合格退回重生成。
5. 入库 `assets/content`，手机端只读。

说明：当前环境没有 `DEEPSEEK_API_KEY`；可以**用当前 DeepSeek 会话分批生成**，或提供 key 后跑自动脚本。小模型不参与内容银行生产。

## 八、审核（五道关 + 180 天模拟）

| 关 | 检查 |
|---|---|
| 1 结构 | 槽位、长度、场景、阶段、JSON 合法 |
| 2 声音 | 句长、标点、口癖、动作道具、禁用词是否匹配圣经 |
| 3 安全 | `InsultGuard` / `ToxicityGuard` / `ClaimGuard`；胡德贵 PUA 边界；性/暴力/自伤一律拒 |
| 4 新颖 | 14 人全库精确/近似去重；跨人设串味；槽位组合合法性 |
| 5 评审 | 规则 + 人工抽样打分（1–5，<4 退回）；同一模型自评有偏，不能只靠它 |

**180 天模拟**：按真实节奏跑心跳/专注/朋友圈/群聊，指标：

- 精确重复 <1%、近似重复 <5%；
- 每人设场景覆盖 ≥80%；
- 口吻标记 ≥70%、跨人设串味 ≤2%；
- 第 1/3/6 个月人工读样本，仍觉得“像她”。

参考外网故事/说话方式：只学结构和语感，**不照抄**；对白由 DeepSeek 重写，避免版权与翻译腔。
