# 语料库与风格源（2026-10-21）

> 目的：把“东京电视台式候选人抽象介绍”变成可用的**旁白/字幕层**，并为 6 个月内容银行建立合法的多风格语料来源。
> 结论先说：**它主要是“语料库/旁白层”的语言风格，不适合当某个 agent 的日常第一人称说话方式；可以作为阿冷的副风格，但不能当主声音。**
> 版权底线：现代电视字幕/节目文案**不直接抄**；只借结构、节奏、冷幽默。直接使用仅限公共领域/CC0/自己生成的内容。
> 五种模式（TVB 商战/周星驰/韩寒/凡人修仙/东京电视台旁白）见《[风格模式与语料扩展](风格模式与语料扩展-2026-10-21.md)》；可下载/可仿写的来源清单见《[语料来源清单](语料来源清单-2026-10-21.md)》。

## 一、东京电视台式“抽象介绍”到底是什么

从公开报道看，其特征不是“介绍政见”，而是**用一句具体、突然、带点冷幽默的话概括一个人**：

- 姓名/年龄/身份 + 一个具体到好笑的细节；
- 不解释、不评价、不煽情；
- 语气平淡，结尾常常突然收住；
- 有时是反差：身份很正式，细节很生活化；
- 有时会翻车：2024 年出现过介绍文与事实不符、节目组更正道歉的情况——**所以“抽象”不等于可以乱编**。

## 二、用在哪里：旁白层，不是聊天层

| 位置 | 用法 | 例子 |
|---|---|---|
| 通讯录/新朋友卡 | 一句话小传 | 「傅沉（34）—— 把‘五分钟’说成‘马上’的人。」 |
| 解锁卡 | 抽象概括 + 一个细节 | 「新朋友：胡德贵（45）—— 体检报告放在抽屉最底层的人。」 |
| 群聊轮次标题 | 给这一轮起个冷标题 | 「第三轮：三个人开始讨论‘稳定’，但没有人真的想稳定。」 |
| 朋友圈卡片 | 旁白式一句 | 「今日小咪：在纸箱里思考人生，思考了四十分钟，睡着了。」 |
| 心跳通知标题 | 偶尔一句，不刷屏 | 「今晚的傅沉：把灯关了一半。」 |
| 每日回顾 | 一天一句 | 「今天，老周投了第三个月的第 7 份简历。」 |

**不要用在**：agent 的每一条聊天回复。那样会变成“旁白在扮演朋友”，破坏陪伴感；聊天仍按人设圣经的第一人称声音。

**可选的副风格**：阿冷是开放麦演员，可以在讲段子时偶尔用这种“字幕式冷幽默”；但只占少数，不改变他的主声音。

## 四、语料来源矩阵（可仿写 / 可直接用）

| 来源 | 借什么 | 许可/用法 |
|---|---|---|
| 东京电视台候选人简介 | 结构、冷幽默、具体细节 | **只仿结构，不抄原文**；不碰真实政治人物 |
| 日本综艺/新闻字幕（テロップ） | 短句节奏、反差、突然收尾 | 只学节奏；不抄字幕 |
| 深夜电台/读者来信 | 低音量、复述、陪伴 | 学语气；原文不抄 |
| 相亲/自我介绍/交友简介 | 自嘲、具体生活细节 | 学结构；不抄个人资料 |
| 天气/季语/岁时记 | 感官、季节、自然 | 公共领域素材可用；自写为主 |
| 青空文库（公有领域日本文学） | 长句、书面语、留白 | 公有领域，可用并标注；翻译需自写 |
| Project Gutenberg（公有领域） | 文学叙事、对话 | 公有领域，可用并标注 |
| Wikipedia / Wikinews | 事实、名词、背景 | CC BY-SA；只取事实，署名；不抄文风长段 |
| 开源项目 README/issue | 技术口吻、冷幽默 | MIT/Apache 等可引用；遵守许可证 |
| 用户提供的文本 | 用户自己的语气 | 需用户授权；只用于其本人 |
| DeepSeek 原创 | 全部成品语料 | 无第三方版权；按项目许可证 |

**“直接使用”的边界**：只对公共领域/CC0/自己生成的内容；现代电视字幕、综艺文案、歌词、小说、社交媒体帖子默认有版权，**不直接搬**。想“像”它们，用结构卡 + DeepSeek 重写，并过相似度审核。

## 五、语料库结构

```kotlin
data class StyleCard(
    val id: String,
    val source: String,       // 来源名
    val license: String,      // public-domain / CC0 / CC-BY-SA / proprietary-reference
    val traits: List<String>, // 结构、节奏、修辞，不存长原文
    val doNot: List<String>,
    val example: String       // ≤30 字，注明来源；TV 类只写“风格示例”不抄原句
)

data class CaptionLine(
    val personaId: String,
    val scene: String,        // CONTACT / UNLOCK / GROUP_ROUND / MOMENT / HEARTBEAT_TITLE
    val text: String,
    val sourceCard: String,
    val review: String
)
```

目录：

```
assets/corpus/
  style_cards.json          # 来源、许可证、风格特征（短）
  captions.json             # 14 人 × 场景的抽象介绍/字幕
  dialogue/<persona>/*.json # DeepSeek 原创对话语料
  sources.md                # 来源、许可证、署名
```

- 不把整段电视文案/小说放进 APK；只存风格卡和原创成品。
- 每批语料记录 `source`、`license`、`review`；审核可追溯。
- 公共领域文本如直接使用，必须在 `sources.md` 署名并保留许可证。

## 六、怎么进内容银行

1. **CaptionBank**：14 人 × 5 场景 × 8–12 条 = 560–840 条，用于通讯录/解锁/群轮次/朋友圈/心跳标题。
2. **DialogueBank**：按人设圣经 + 风格卡，由 DeepSeek 生成；每条带 `styleCard` 标签，不混入第一人称聊天。
3. **群聊开场/轮次标题**：可用 CaptionBank；正文仍由各人设第一人称说。
4. **叙事线**：章节标题可用“抽象介绍”风格，正文用人设自己的声音。

## 七、审核新增

- **风格审核**：像不像该来源的结构；不得出现来源原文的长片段（n-gram 比对）。
- **版权审核**：`license` 必须是 public-domain / CC0 / 自有 / 已授权；TV/综艺类只能是 `proprietary-reference`，不入库原文。
- **事实审核**：抽象介绍里的细节必须来自小传或已核验事实；不编真实人物、不碰政治。
- **语气审核**：旁白层不能进入聊天第一人称；阿冷的副风格占比 ≤20%。
- **人工抽检**：每批 10%，重点看“像不像人话”和“有没有冒犯”。

## 八、下一步

1. 先做 **CaptionBank 试点**：14 人 × 5 场景 × 8 条（560 条），DeepSeek 生成 + 审核。
2. 同步扩充 **StyleCard**：东京电视台、综艺字幕、深夜电台、相亲简介、青空文库、Gutenberg、开源文档、技术社区。
