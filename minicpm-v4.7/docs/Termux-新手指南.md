# Termux 新手指南：在 vivo X100 Pro 上跑 MiniCPM-V 4.7 1B

> ### ⚡ 已经有全自动版本了，不用照着本文敲命令
>
> 电脑上手机插好数据线，**双击 `全自动部署到手机.cmd`**，脚本会用 adb 的 `run-as` 以 Termux 身份把全部步骤做完：
> 搬模型（手机内部复制，233 MB/s）→ 换清华源 → 装编译工具 → 传源码 → 编译 → 建桌面一键启动入口。
> **手机上完全不需要输入任何命令。** 进度随时看：`.\scripts\auto-setup-phone.ps1 -Action status`
>
> 本文保留，是为了：（1）你想知道每一步到底在干什么；（2）自动流程某一步失败时，你能看懂报错、手动接手。

写给**第一次用 Termux** 的人。按顺序照做即可，每一步都写了"你会看到什么"和"出错了怎么办"。

预计耗时：准备 15 分钟 + 编译 20～40 分钟。全程手机不需要联网（除了装编译工具和克隆代码那一步）。

---

## 第 0 步：先搞明白你的「16+16G」是什么

你说的「16+16G，最大支持动态扩展 16GB 运行内存，会占用部分存储空间」——这条信息很关键，先讲清楚：

**那是闪存当虚拟内存，不是真的加了内存。** 它是把 UFS 存储划一块出来，当内存不够时把数据换出去。对大模型推理来说：

- **帮不上忙，反而拖后腿。** 模型推理吃的是内存带宽（真内存几十 GB/s），UFS 4.0 只有大约 1～4 GB/s。一旦模型数据被换到闪存上，速度会掉到十分之一以下，表现就是"卡住不动"。
- **它还占存储**，而这次我们正需要存储空间。
- **官方 35B 能跑在手机上，恰恰不是靠这个机制**——那是 LES：有预测、有调度的按需读取专家权重，和系统无脑换页是两回事。

**所以建议：跑模型之前把「运行内存扩展」调小或关掉。**

> 设置路径（OriginOS）：`设置 → 运存与存储空间 → 运行内存扩展`（不同版本可能在 `设置 → 更多设置` 里）。

16GB **物理**内存跑 1B 模型（权重才 2.2GB）绰绰有余，根本用不到扩展。

**顺便看下存储空间够不够：**

| 用途 | 需要 |
|---|---|
| 三个模型文件 | 2.2 GB |
| Termux 本体 + 编译工具链 | 约 1.5 GB |
| 编译 llama.cpp 的临时文件 | 3～4 GB |
| **合计** | **约 7～8 GB 空闲** |

手机 `设置 → 存储` 里看一眼可用空间。

## 第 1 步：认识接下来要用的东西

**Termux 是什么？** 一个装在安卓手机里的 Linux 命令行 App，**不需要 root**，不刷机、不影响保修。我们要用它来编译并运行 llama.cpp。

打开后你会看到一个**黑底白字、带 `~ $` 提示符**的界面。这就是全部的交互方式——打字，回车，看输出。

### 三个必须学会的操作（新手最容易卡在这）

| 想做的事 | 怎么做 |
|---|---|
| **粘贴** | 在终端任意位置**长按屏幕** → 弹出菜单 → 点 **Paste** |
| **停止正在运行的程序**（比如服务端） | **音量减 + C**（Termux 里音量减键就是 Ctrl 键） |
| **滚动看历史输出** | 手指在屏幕上上下滑动 |

屏幕底部可能有一排 `ESC CTRL ALT TAB ← → ↑ ↓` 的键，那是辅助键，用不到可以忽略。

> ⚠️ **中文输入提示**：Termux 里打中文很别扭（输入法候选框和终端会打架）。**所有需要用中文的地方都留到最后的浏览器界面里做**，终端里只粘英文命令。这也是我把命令都准备成"复制粘贴即可"的原因。

## 第 2 步：手机准备（3 件事）

**1）打开开发者模式**
`设置 → 关于手机 → 版本信息` → 连点 **版本号** 7 次 → 提示"你已处于开发者模式"。

**2）打开 USB 调试**
`设置 → 系统 → 开发者选项` → 打开 **USB 调试**。

**3）用数据线连电脑**
连上后手机会弹窗 **"允许 USB 调试吗？"** → 勾选"一律允许" → 确定。
（如果没弹窗：拔掉数据线重插，或把 USB 模式从"仅充电"改成"传输文件/MTP"。）

---

## 第 3 步：电脑上一条命令推完所有东西

**最省事：在电脑上双击根目录的 `推送模型到手机.cmd`**（内部强制绕过 PowerShell 执行策略，不会撞"未数字签名"的报错）。

或者用命令行：

```powershell
cd "D:\MiniProj\CellPhone Helper\minicpm-v4.7"
.\scripts\push-to-phone.ps1

# 如果报「未对文件…进行数字签名」，改用：
powershell -ExecutionPolicy Bypass -File .\scripts\push-to-phone.ps1
```

这条命令会依次做完：

1. 检查 adb 与手机连接（没连上会告诉你具体缺哪一步）
2. **安装 Termux**（官方 v0.118.3 arm64 安装包，已核对 SHA256；手机已装则自动跳过）
3. 在手机建立 `/sdcard/Download/minicpm` 目录
4. 推送 3 个模型文件（约 2.1GB，实测 30MB/s 左右，约 1 分钟；**已存在且大小一致的文件会自动跳过**）
5. 推手机端脚本 `termux-setup.sh`
6. **逐个回读字节数确认传输完整**，有文件大小不一致会明确报警

看到每个文件都显示 `OK ... 字节数一致` 就算成功了。

> 为什么不让你在手机上敲命令？因为 2.1GB 的文件靠手机浏览器下载慢，而中文/长命令在 Termux 里手打极容易出错。推过去最省事。
>
> 如果你不想用数据线，也可以手动把 `models/` 里三个 `.gguf` 拷到手机 `Download/minicpm/` 目录，效果一样。

---

## 第 4 步：第一次打开 Termux

打开 Termux，等几秒让它初始化完成，看到 `~ $`。

**先授予存储权限**——粘贴这一行并回车：

```bash
termux-setup-storage
```

手机会弹出权限询问，点 **允许**。

> 如果没弹窗：去 `设置 → 应用 → Termux → 权限 → 存储` 手动打开。

**把脚本复制到 Termux 的家目录**（重要：安卓 10 以后 `/sdcard` 上的文件不允许直接执行，必须复制过来）：

```bash
cp ~/storage/downloads/minicpm/termux-setup.sh ~/
```

**验证一下脚本在不在：**

```bash
ls -l ~/termux-setup.sh
```

---

## 第 5 步：换成国内软件源（**必做，否则会等到怀疑人生**）

Termux 默认的软件源在国外，国内直接 `pkg update` 可能几分钟没反应或者报连接失败。

粘贴运行：

```bash
termux-change-repo
```

会出现一个蓝底的文字菜单，操作方式：

1. **方向键上下**移动光标
2. **空格键**勾选/取消勾选
3. **回车键**确认

先在列表里选中 `Main repository`（主仓库），回车；下一页选择镜像，挑一个：

- `mirrors.tuna.tsinghua.edu.cn`（清华，推荐）
- `mirrors.ustc.edu.cn`（中科大）

选好后回车确认。如果菜单里还提示 `Root repository` 之类，同样处理。

**然后更新软件列表：**

```bash
pkg update -y && pkg upgrade -y
```

这一步可能要几分钟，会刷很多行字，正常。

## 第 6 步：搬模型并校验（约 1 分钟）

粘贴回车：

```bash
bash ~/termux-setup.sh setup
```

你会看到它把模型从 Download 复制到 Termux 的私有目录，然后**逐个做 SHA256 校验**：

```
📦 来源目录：/data/data/com.termux/files/home/storage/downloads/minicpm
   复制 MiniCPM-V-4_7-1B-Q4_K_M.gguf ...
   ...
🔐 校验 SHA256 ...
MiniCPM-V-4_7-1B-Q4_K_M.gguf: OK
mmproj-model-f16.gguf: OK
dspark-MiniCPM-V-4_7-1B-F16.gguf: OK
✅ 模型就绪
```

**必须三个都显示 OK**。如果出现 `FAILED`，说明传输过程中文件损坏了，回到第 3 步重新推一次。

> 为什么要复制一份？一是私有目录执行权限没问题、读写更快；二是 `/sdcard` 的访问在后台任务里容易被系统掐断。

---

## 第 7 步：编译 llama.cpp（最久的一步）

**先做准备**：插上充电器、把 Termux 留在前台、`设置 → 电池` 里允许 Termux 后台高耗电。然后运行编译脚本，它内部会自动申请唤醒锁。

粘贴回车：

```bash
bash ~/termux-setup.sh build
```

它会依次：装编译工具（`git cmake clang make`）→ 克隆 llama.cpp → 配置 → 编译。

**心理预期：**

- 装工具 3～10 分钟，克隆代码 1～3 分钟，**编译 15～40 分钟**
- 中途手机会**明显发热**，这是正常的（8 个大核全在跑）
- 屏幕会刷大量编译信息，只要没出现 `error:` 就不用管
- 建议别锁屏、别切走 App（OriginOS 杀后台比较激进）

**成功的标志：**

```
✅ 编译完成，产物：
-rwx...  build/bin/llama-mtmd-cli
-rwx...  build/bin/llama-server
```

**如果报错：**

| 报错 | 处理 |
|---|---|
| `virtual memory exhausted` / 卡死被杀 | 内存不够，改用 `bash ~/termux-setup.sh build` 前先编辑脚本把 `-j8` 改成 `-j4`：`sed -i 's/-j8/-j4/' ~/termux-setup.sh` 再跑 |
| 下载源码卡住 | 换源那步没做成功，重新执行第 5 步 |
| `No space left on device` | 存储不够，删点东西（或先关运行内存扩展）后重跑 |
| 中途 Termux 被杀 | 重新运行同一条 `build` 命令即可，脚本会跳过已完成的克隆步骤 |

---

## 第 8 步：跑起来

```bash
bash ~/termux-setup.sh serve
```

看到类似 `main: server is listening on http://127.0.0.1:8080` 就成功了。**这个终端窗口不要关**。

现在打开手机的浏览器（vivo 自带浏览器、Chrome 都行），地址栏输入：

```
http://127.0.0.1:8080
```

进去就是聊天界面。**在这里可以随便打中文**：

- 直接输入问题就是纯文本对话
- 界面里有上传图片的按钮，选相册里的照片，就能让它读图、识别文字、描述画面
- 想停止服务：回到 Termux，按 **音量减 + C**

**日常再用的命令**（下次开机只要这三步，不用重新编译）：

```bash
bash ~/termux-setup.sh check     # 检查文件齐不齐
bash ~/termux-setup.sh serve     # 起服务
```

**想用命令行直接问一张图**（快速测试）：

```bash
bash ~/termux-setup.sh ask ~/storage/shared/DCIM/Camera/你的照片.jpg "读出图中所有文字"
```

## 第 9 步：出问题时的自查清单

| 现象 | 原因与解决 |
|---|---|
| 浏览器打不开 `127.0.0.1:8080` | Termux 里的服务是否还在跑？窗口里有没有报错？先 `bash ~/termux-setup.sh check` |
| 回答里出现一大堆 `<think>` | 服务脚本已经默认帮你关了 thinking；如果你是用 `ask` 命令行模式，它会带思考过程，属正常 |
| 速度慢、卡顿 | 检查①运行内存扩展是否已关②是否在充电时跑③是否同时开着游戏/相机 |
| Termux 切到后台就被杀掉 | `设置 → 电池 → 后台高耗电` 允许 Termux；跑之前脚本会自动 `termux-wake-lock` |
| 手机很烫 | 正常，降频后变慢也是正常的；摘掉手机壳、别边充边跑大图 |
| `cp: cannot stat ...` | 第 3 步没推成功，检查手机 `Download/minicpm/` 目录里有没有那 4 个文件 |
| `Permission denied` 执行脚本 | 你直接在 `/sdcard` 上执行了。必须先 `cp` 到 `~/` 再 `bash ~/...` |

## 附：这套方案的技术依据（供你放心）

- 上游 `ggml-org/llama.cpp` 的 **PR #29416（Support MiniCPM-V 4.7）已于 2026-10-10 合入主线**。我在电脑上用同版本的预编译包（b11671）实测跑通了 1B 与 35B 的图文问答。
- 官方 GGUF 仓库里的 `mmproj-model-f16.gguf` 就是视觉投影器，**这两个文件必须配套使用**，混用会加载失败。
- 三个文件的 SHA256 是官方仓库提供的，脚本逐个校验，避免传输损坏导致"模型能加载但答得离谱"这种难查的问题。
